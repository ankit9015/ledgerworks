# Measurement harness: run-to-run variance (C2.2)

All data is **synthetic** (the 10M-row Ledgerline seed, `pnpm seed --yes`, seed `20251001`), cloned in full into a shadow (`docs/benchmarks/shadow-clone.md`). Design and interpretation: DECISIONS.md D34 to D36. Raw files: `raw/c2.2-variance-<case>-<label>-<time>.json`, one per case and experiment; every file holds all 10 repetitions with every run, the plans, the machine description, the container limits (including the `cpuset`) and, from the final experiment on, whether the database was quiet.

|               |                                                                                                                                                                                                                                    |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Method        | each case: **10 repetitions**, each a complete `measureQuery` with **3 warmup + 20 measured runs** (DDL: `measureDdl`, 3 runs per repetition); statistics over the ten repetition medians                                          |
| Shadow        | full copy, `ledgerworks/shadow-postgres:16.15-hypopg1.4.3`, **2 CPUs / 3 GiB**, no swap, `shared_buffers` 768 MB, planner settings copied from the source; settled with `settleShadow` first                                       |
| Machine       | Intel Core i5-1135G7 (4 cores / 8 threads), 19.8 GB RAM, Windows 11, Docker Desktop VM with 8 CPUs / 9.6 GiB; node 22.13.1                                                                                                         |
| Not dedicated | a developer laptop with other applications running; CPU frequency not fixed; the script started nothing else                                                                                                                       |
| Statement     | `usage-read-*`: Ledgerline's `GET /v1/usage` page 1 for the largest tenant, 7-day window (`docs/benchmarks/sql/usage-read-p1-*.sql`), run as the shadow administrator (RLS bypassed), so absolute numbers are lower than the API's |

## Final experiment (label `final`)

| Case                                                                       | mean of p50 (wall) | range of the 10 p50s | CV of p50 across repetitions | (max-min)/mean | mean of p50 (server) | CV of server p50 | CV of the 20 runs inside one repetition (mean, max) |
| -------------------------------------------------------------------------- | ------------------ | -------------------- | ---------------------------- | -------------- | -------------------- | ---------------- | --------------------------------------------------- |
| usage-read-after-E1 (index scan, top 51)                                   | 1.258 ms           | 1.121 to 1.771 ms    | **15.0%**                    | 51.6%          | 0.143 ms             | 9.3%             | 17.5% (max 27.1%)                                   |
| usage-read-before-E1 (the alias bug: sorts 64k rows)                       | 53.0 ms            | 44.2 to 66.7 ms      | 11.5%                        | 42.3%          | 56.2 ms              | 4.4%             | 28.7% (max 52.3%)                                   |
| usage-aggregate-month (about 270k rows)                                    | 87.2 ms            | 82.7 to 92.5 ms      | 3.7%                         | 11.2%          | 92.5 ms              | 4.6%             | 23.4% (max 52.3%)                                   |
| credit-balance-update (one row, rolled back)                               | 0.982 ms           | 0.835 to 1.261 ms    | 11.7%                        | 43.3%          | 0.068 ms             | 17.7%            | 21.7% (max 39.6%)                                   |
| ddl-add-column-volatile-default (200,000-row table, 3 runs per repetition) | 282 ms             | 249 to 330 ms        | 9.6%                         | 28.8%          | -                    | -                | 11.4% (max 35.3%)                                   |

The harness's own `quiet` flag (no autovacuum, no checkpoint during the measurement): true for all 10 repetitions of every query case, and for 9 of 10 DDL repetitions.

**Reading it.** A single run varies by 17% to 29% (CV), the median of 20 much less, and the median of one repetition varies by 4% to 15% (CV) between repetitions, with the largest (max-min)/mean spread of 52% for the sub-2 ms queries. What counts as a real difference is in DECISIONS.md D36: compare in the same session, interleaved; call a difference real above about 40% for queries of 50 ms or more, a factor of 2 for queries under 2 ms (use the server time), and about 50% for DDL durations.

The `quiet` flag exists only in the code from the final experiment on.
